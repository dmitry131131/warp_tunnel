# Симулятор Warp ASM

Симулятор на C++17 полностью считывает входной файл, разбирает инструкции,
разрешает ссылки на метки и последовательно исполняет программу.
Командная строка принимает один аргумент — путь к программе.

Из корня проекта сборка и запуск выполняются так.

```bash
cmake -S ASM2IR/SIM -B build/sim
cmake --build build/sim
./build/sim/warp_sim ASM2IR/app.asm
```

После разбора текущего приложения печатается следующая строка,
затем начинается исполнение и открывается окно SDL.

```text
Parsed 221 instructions, 25 labels, entry instruction 0
```

Для сборки нужны компиляторы C/C++ и SDL2 с заголовочными файлами.
Графика и ввод используют существующую реализацию `src/sim.c`.

## Исполнение

В [simulator.h](simulator.h) и [simulator.cpp](simulator.cpp) определён
класс `Simulator`. Он получает ссылку на разобранный `Program`, который
должен существовать до завершения работы симулятора, и предоставляет
метод `run()`. Каждый вызов `run()` начинает исполнение с `entry_point`,
обнуляет 64 регистра и сбрасывает состояние памяти и стека возвратов.
После завершения значения регистров доступны через `registers()`.

Счётчик `pc` хранит индекс инструкции в `Program::instructions`.
Перед вызовом обработчика он увеличивается на единицу, а обработчики
переходов могут заменить его целевым индексом. Для каждого из 30 кодов
`Opcode` написана отдельная функция `handle_*`, которую вызывает
`dispatch`; суффикс разрядности и предикат обрабатываются внутри
соответствующего семейства команд.

`call` кладёт индекс следующей инструкции в отдельный стек возвратов
`std::vector<std::size_t>`, а `ret` извлекает его. `ret` при пустом стеке
завершает программу. Аргументы, результаты и временные значения
подпрограмм хранятся в регистрах по соглашениям ASM-программы,
поэтому дополнительный стек данных для текущего набора команд не требуется.

## Модель памяти

Память представляет собой заранее выделенный массив 64-битных слов
`std::vector<std::uint64_t>`, по умолчанию из 1 048 576 элементов,
то есть 8 МиБ. Второй аргумент конструктора `Simulator` позволяет задать
ёмкость в словах. Рядом хранится массив признаков записи в каждое слово
и список границ выделений.

Адрес в регистре — байтовое смещение от начала массива, поэтому первый
`alloc` возвращает 16. Нулевой адрес зарезервирован, каждое выделение
выровнено на 16 байт. `alloc` последовательно отводит N слов из свободного
конца массива, а `ld/st` вычисляют адрес элемента по знаковому индексу
в словах. Базовый адрес должен указывать на элемент существующего
выделения; разрешены отрицательные индексы от внутренних элементов,
если итоговый адрес остаётся в том же выделении.

Симулятор проверяет выравнивание, принадлежность выделению, переполнение
памяти и чтение слова до первой записи. Переход из одного выделения
в другое через индекс считается ошибкой даже при соседстве массивов.
При завершении или ошибке исполнения память принадлежит объекту
`Simulator` и освобождается при его уничтожении; следующий `run()`
сбрасывает выделения и признаки записи.

## Инструкции симулятора

Обработчики `init`, `exit`, `flush`, `putpixel`, `rand`, `hasclick`
и `getclick` вызывают одноимённые функции интерфейса `sim.h`.
Среда SDL инициализируется один раз перед первой инструкцией,
которой она нужна, включая `rand` для установки начального состояния
генератора. Явный `init` инициализирует среду заранее и при уже работающей
среде сохраняет её состояние.

Явный `exit` закрывает активную среду. При завершении `run()` или ошибке
активная среда также закрывается через `simExit()`. В текущей реализации
этой функции нужно закрыть окно, чтобы закончить ожидание события SDL_QUIT.
После `exit` инструкция, использующая среду, может инициализировать её снова.
Чисто арифметическая программа выполняется без открытия окна.

## Внутреннее представление

В [parser.h](parser.h) описаны типы и интерфейс парсера.

- `Program::instructions` хранит инструкции в порядке исходного файла.
  Каждая `Instruction` содержит `Opcode`, разрядность, предикат сравнения,
  список операндов и номер исходной строки.
- `Operand` — вариант из `Register`, `Immediate` и `LabelTarget`.
  Регистр хранит индекс от 0 до 63, литерал — 64-битное представление,
  а ссылка на метку — имя и уже разрешённый индекс инструкции.
- `Program::labels` сопоставляет именам меток индексы инструкций и строки
  определения. Несколько разных меток могут указывать на одну инструкцию.
- `Program::entry_point` указывает на метку `app`, если она есть,
  иначе на первую инструкцию, то есть индекс 0.

Функция `parse_file(path)` полностью загружает файл в строку, затем
передаёт её функции `parse(source)`. Разбор сначала собирает инструкции
и определения меток, после чего разрешает прямые и обратные ссылки
в `jmp`, `call`, `bcmp` и `brect`.

## Синтаксис и ошибки

Поддерживаются все 30 команд и семейств из [описания ISA](../README.md),
суффиксы разрядности 8/32/64, предикаты `eq/slt/sgt`, комментарии
после `;`, пустые строки и окончания строк LF/CRLF. Метки задаются
на отдельных строках как `name:`, операнды инструкций разделяются
запятыми, имена чувствительны к регистру.

Десятичные и шестнадцатеричные литералы допускают значения от −2^63
до 2^64−1, включая отрицательную шестнадцатеричную запись.
Отрицательные числа сохраняются в дополнительном коде.
`alloc` требует положительный литерал, число байт которого помещается
в `size_t`; регистр результата всегда должен иметь вид `x0`–`x63`.

Парсер проверяет мнемонику, суффиксы, количество и типы операндов,
диапазоны чисел и регистров, уникальность и существование меток.
Пустая программа и метка после последней инструкции считаются ошибками.
При ошибке разбора выбрасывается `ParseError` с номером строки,
а частично разобранная программа вызывающему коду не возвращается.

CLI печатает сообщение вида `file.asm:строка: описание` в stderr
и возвращает код 1, при успешном исполнении возвращает 0.
Ошибки чтения файла также приводят к коду 1.
Ошибки исполнения представлены типом `ExecutionError` с номером
исходной строки. Проверяются нулевые делители, переполнение знакового
деления и остатка, величины сдвигов, `abs(-2^63)`, допустимость доступа
к памяти и координаты `putpixel` после сужения до 32 бит.
Достижение конца файла без завершающего `ret` также считается ошибкой.
